第二章

技术栈与核心系统架构

Akileas 秉承"异构硬件各司其职"的设计哲学，将计算密集型与分支密集型任务严格划分， 避免盲目移植 GPU 或将所有逻辑堆在主线程的传统弊端。

2.1 分层架构

整个工程遵循单向向内的依赖方向，自顶层应用逻辑逐层下沉到存储与安全边界。

2.2 核心技术选型一览

  • 编程语言：Rust 2024 Edition，利用零成本抽象与强类型系统规避竞态，以编译期内存管理代替运行时 GC。
  • UI 与图形引擎：GPUI（Zed 团队开发），采用全 GPU 渲染管线（macOS 下为原生 Metal，Windows / Linux 下支持 DirectX 12 / Vulkan），支持 120Hz / 144Hz 超高刷新率与亚像素字体渲染。
  • 内存分配引擎：mimalloc（Microsoft），替代系统默认 malloc，针对小对象和多线程场景优化，消除堆内存碎片与抖动。
  • 文本数据结构：Ropey，基于 B-Tree 的不可变绳索（Rope）结构，支持大规模文本的 O(log N) 插入、删除与无拷贝切片。
  • 语法增量分析：Tree-sitter（tree-sitter-md），采用两级架构（块级语法树与行级内联语法树），基于字节范围实施局部"外科手术式"增量修剪。
  • TeX 盒模型排版：Ratex，纯 Rust 实现的宏包解析与 Knuth-TeX 盒模型求解算法，脱离任何 JavaScript / Node / 浏览器运行时。
  • 矢量图表编译器：Rusty-Mermaid，纯 Rust 将 Mermaid DSL 编译为不可变 GPU 矢量图元（路径、多边形、贝塞尔曲线），内建 360x240 局部着色器放大镜。
  • 出版级排版输出：Typst 0.15，现代化排版框架，将 Markdown AST 转换为 Typst 格式直出高精矢量 PDF。

2.3 异构计算硬件与线程分工模型

四类执行单元各自承担性质完全不同的工作：主线程只做极轻量的物理投影， CPU 向量单元负责扫描，后台线程池负责解析与求解，GPU 只做最终的光栅化。

2.5 Tree-sitter 双层增量解析与零拷贝 Rope Chunks 流式驱动

传统编辑器在传递文档给解析器时，往往需要调用 to_string() 分配一个数十兆字节的巨大连续内存， 导致剧烈的内存分配与 GC。Akileas 的突破性方案有两点。

  1. 直接流式读取 Rope Chunks：通过自定义流式读取器， Tree-sitter 直接读取 Ropey 分块内部的不连续内存页，零内存拷贝。
  2. 两级语法树隔离：块级语法树（Block Tree）仅划分段落、标题、代码块、引用与列表边界； 行级语法树（Inline Tree）按需挂载在变化块上。当修改正文字符时，块结构保持不变， 仅受影响的那一行重新解析行内语法，周围 99,999 行完全复用既有树节点。

NOTE

零拷贝流式读取意味着打开十万行文档时，内存中不会出现第二份完整的文档副本， 冷启动的 1.84 秒中绝大部分耗时来自首次权威解析，而非文本搬运。

2.7 对数级虚拟化高度树 DocumentHeightMap

在长达十万行的文档中，如果使用线性累加计算总高度，滚动视口或拖拽滚动条将引发灾难性的计算瓶颈。 Akileas 实现了 DocumentHeightMap 对数级高度树。

  • 前缀和高度累加树：以分块构建累积高度索引。当用户编辑第 500 行时， 仅更新局部块的高度差值，不需要遍历全篇。
  • O(log N) 二分快速定位：鼠标拖拽滚动条到 85% 位置时， 通过二分查找在数微秒内直接命中精确行号与行内像素偏移。
  • 渲染平滑防抖：将非视口内的未知行预估为均值高度，当用户平滑拖拽时逐步细化， 彻底消除滚动条跳跃与抖动。

2.8 存储安全韧性：SaveTicket 保序、原子落盘与灾难恢复

针对写文件竞态与异常断电场景，Akileas 建立了高可靠的存储安全体系。

flowchart TD
    SaveReq["触发保存（Cmd+S / 自动定时保存）"] --> Ticket["分配递增票据 SaveTicket（seq = N）"]
    Ticket --> Queue["进入文件专属并发队列"]
    Queue --> Check{"持锁期间校验：<br/>latest_sequence == N ?"}

    Check -->|否（已有更新的保存任务）| Drop["自动废弃过期任务（杜绝旧写覆盖新内容）"]
    Check -->|是（允许写入）| Tmp["1. 同目录下创建 .tmp.UUID 临时文件"]
    Tmp --> Write["2. 写入完整数据并计算 CRC32"]
    Write --> Fsync["3. 调用 OS 底层 sync_all / fsync 强制物理扇区落盘"]
    Fsync --> Rename["4. 原子覆盖（POSIX rename / Windows MoveFileEx）"]
    Rename --> TM["5. 本地时光机 LocalHistoryStore 记录滚动版本（至多 100 份）"]

断电恢复与本地时光机

  • RecoveryJournal 恢复日志：每次编辑流式追加带 CRC32 校验的轻量日志； 即使遭遇断电关机，再次启动时也会自动校验并秒级重放恢复。
  • LocalHistoryStore 本地时光机：完全不依赖 Git。每次保存自动在本地数据库记录一份历史版本快照， 支持内置 Myers Diff 算法进行字符级增删对比，随时一键还原。
