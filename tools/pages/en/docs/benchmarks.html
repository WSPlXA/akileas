Chapter I

Performance & Benchmarks

Every number on this page was measured on a real Akileas build — a native Rust/GPUI editor running against genuine TextBuffer instances, the authoritative Markdown parser, and chunked line storage. No synthetic stubs, no headless browsers.

1.1 Test Environment

The measurements below were taken on the following local machine and runtime environment.

  • Test system: Windows 11 (10.0.26200-SP0) / AMD64 (x86_64)
  • Processor: Intel64 Family 6 Model 151 (Intel 12th/13th/14th Gen Core architecture)
  • Compiler and build: Rust 1.98.0+, bench profile (cross-module release-grade optimisation enabled, with native SIMD instruction dispatch)
  • Benchmark source: benches/editor_latency.rs, driving a real TextBuffer, the authoritative Markdown parser, and chunked line storage

Unless a row states otherwise, figures in the tables are the median of a repeated sampling run on this machine.

NOTE

The pending projection stage is the instantaneous slice of uncoloured physical lines executed on the UI main thread after the user presses a key. On this machine, a measured 100,000-line document needs only 37 microseconds (0.037 ms): characters and the cursor are drawn on screen immediately, and the frame cost is under 1% of the 120 FPS budget (8.33 ms). Authority parsing is the background worker thread pool that incrementally scans Rope chunks and dispatches a new snapshot. On this machine, a measured 100,000-line document needs only 0.703 ms, after which the highlight syntax is injected smoothly through a lock-free atomic Arc swap.

1.3 Multi-Scenario Persistence Stress Test

Persistence stress test across multiple editing scenarios: 100,000 lines, snapshots retained with AKILEAS_BENCH_RETAIN=1, and 40 sample cycles per mode.

[Windows 11 / Intel Core local 100,000-line persistent syntax tree stress measurement]
├─ Plain character input replacement (replace)  : Pending 0.038 ms │ Authority p50 = 0.716 ms │ p95 = 0.786 ms
├─ Alternating insert/delete characters (typing) : Pending 0.038 ms │ Authority p50 = 0.712 ms │ p95 = 1.218 ms
├─ Inline emphasis syntax change (syntax)       : Pending 0.038 ms │ Authority p50 = 0.716 ms │ p95 = 0.934 ms
├─ Random jumps across paragraphs (distrib)     : Pending 0.044 ms │ Authority p50 = 0.466 ms │ p95 = 0.626 ms
└─ Structural heading reflow (block)            : Pending 0.085 ms │ Authority p50 = 997.10 ms │ p95 = 1162.17 ms

Core conclusions

  1. Day-to-day high-frequency input is extremely fluid: character entry, backspace deletion, inline bold highlighting, and cross-paragraph editing all keep background incremental parsing between 0.46 ms and 0.71 ms, while the physical projection needs only 38 microseconds.
  2. Structural syntax isolation provides a guarantee: when typing # triggers a syntax reflow of the heading block, the parser must traverse the entire syntax tree (about 997 ms); but because the Stage 1 projection mechanism needs only 85 microseconds, the user's keystrokes and cursor feedback never stutter or drop a frame.

1.5 Zero-GC Memory Profile & Bounded Caches

Memory and cache budget

  • Resident memory baseline: a lightweight document needs only 25 MB ~ 45 MB, while a giant 100,000-line document holds steady at 60 MB ~ 110 MB.
  • Total budget ceiling: kept within 150 MB.
pie title Resident memory and cache budget (150 MB ceiling)
    "Runtime and Rope buffers" : 45
    "Image LRU cache" : 64
    "Mermaid vector geometry cache" : 32
    "TeX box-model DisplayList" : 32

Cache safeguards

  • Image cache: a hard ceiling of 64 MiB, at most 256 entries, and at most 8 concurrent decode tasks; oversized or anomalous images are intercepted, ruling out OOM.
  • Mermaid vector geometry cache: a 32 MiB ceiling caching CPU tessellation and path topology; panning only adjusts the coordinate matrix.
  • TeX box-model cache: a 32 MiB LRU cache, preloading 19 KaTeX vector font outlines.
  • Agent analysis boundaries: the front-matter safety fence scans at most the first 64 KiB or 512 lines and retains at most 128 top-level properties; directory traversal skips build, target, and .git; the resident index text is at most 4 MiB.

Through the Rust ownership model and the Microsoft mimalloc global allocator, the garbage-collection (GC) frame drops typical of Electron / Chromium editors are eliminated entirely.

1.7 Reproducing the Benchmarks

Run the following commands from the repository root to reproduce the measurements on your own machine.

# 1. Compile the stress suite (without network access and default platform dependencies)
cargo bench --bench editor_latency --no-default-features --offline --no-run
# 2. Run the default 10,000 and 100,000 line standard benchmarks
cargo bench --bench editor_latency --no-default-features --offline
# 3. Run the persistence multi-mode test retaining old snapshots (typing, syntax, distributed, block)
for mode in typing syntax distributed block; do
  AKILEAS_BENCH_RETAIN=1 AKILEAS_BENCH_LINES=100000 AKILEAS_BENCH_SAMPLES=40 \
    AKILEAS_BENCH_MODE="$mode" cargo bench --bench editor_latency --no-default-features --offline
done

TIP

Keep the machine otherwise idle while benchmarking: cold-start and p95 figures are sensitive to background load and to thermal throttling on laptop CPUs.
