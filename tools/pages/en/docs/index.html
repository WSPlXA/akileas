Documentation

The Akileas Technical Manual

Four chapters covering measured performance, the systems underneath the editor, every user-facing capability, and the specification for capturing the interface. Written for engineering reviews, product demonstrations, and architecture briefings.

What this manual covers

Akileas is a native, latency-first Markdown editor built on Rust 2024 and GPUI, with a pure-Rust LaTeX and Mermaid rendering core and publication-grade Typst vector PDF export. It holds to a single performance invariant: the UI thread never waits.

Whether you are editing a thousand-line note or a hundred-thousand-line engineering manuscript, the physical response stays sub-millisecond. The chapters below document how that is measured, how it is built, how it behaves in daily use, and how to photograph it.

  1. Chapter I Performance & Benchmarks Microsecond-scale pending projection, authority parse latency at 10k and 100k lines, SIMD search throughput, memory ceilings, and the full editor comparison matrix.
  2. Chapter II Stack & Architecture Rust 2024 and GPUI, heterogeneous CPU/GPU division of labour, the dual-stage hot path, zero-copy Tree-sitter parsing over Rope chunks, and crash-safe storage.
  3. Chapter III Usage & Feature Guide In-place hybrid WYSIWYG, split views, outline and search, the Git-free time machine, native LaTeX and Mermaid, the Agent workbench, and Typst PDF export.
  4. Chapter IV Screenshot Guide Capture environment and conventions, the shared demo document, and a shot-by-shot brief for the eight canonical interface screenshots.

How to use this material

The four chapters are written to be cited independently. Each opens with the claim it supports and backs it with measurements, diagrams, or reproducible commands.

Technical briefings

Lead with the microsecond-scale benchmark tables in Chapter I and the heterogeneous-compute and dual-stage hot-path diagrams in Chapter II.

User documentation

Chapter III stands alone as an onboarding guide. The shortcut reference at the end maps every action across macOS, Windows, and Linux.

Visual and presentation material

Follow Chapter IV to capture the eight canonical screenshots into assets/screenshots/. Each scene lists its subject, staging steps, and window size.

Every benchmark figure in Chapter I was measured on the reference machine recorded in that chapter. Reproduce them with the commands in the final section rather than quoting them out of context.
